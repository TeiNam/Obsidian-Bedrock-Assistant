### Graph RAG 検索

ベクトル類似度だけでなく、ノート間のリンクをたどって関連ノートを広げます。検索のために追加のLLM呼び出しは行いません（呼び出しは通常のチャット応答の分だけです）。

処理の流れ：

1. 質問の埋め込みとチャンク埋め込みを比較し、シード（起点）ノートを選ぶ
2. シードのアウトリンク・バックリンクをたどって近傍ノートへ拡張する
3. 各候補の関連性を求める。シードは正規化した類似度そのもの、近傍ノートは `0.6 × 近傍ノート自身の類似度 + 0.4 × シードの類似度` になる
4. 関連性が 0.55 未満の候補を除外する（この判定はグラフ距離による減衰を適用する**前**の関連性に対して行います）
5. 残った候補に減衰を掛けて統合スコアを出す：`統合スコア = 関連性 × 0.5^hop`（0.0〜1.0）

| 設定 | デフォルト | 説明 |
|------|-----------|------|
| グラフ探索の深さ | 1 | リンクをたどって拡張するhop数（0〜3）。0でグラフ探索を無効化 |
| チャンク最大サイズ | 2000 | 単一チャンクの最大文字数 |
| チャンク重複サイズ | 200 | 隣接チャンク間の重複文字数（チャンク最大サイズより小さい値） |

### Second Brain レイヤー

Graph RAG の「読み取り」の上に「書き込み」を重ねるレイヤーです。**オプトインで、デフォルトは無効です。無効の間、ノートが自動的に作成・変更・削除されることはありません。**

設定 → Assistant Kiro 設定 → Second Brain で有効化します。

| 設定 | デフォルト | 説明 |
|------|-----------|------|
| Second Brainを有効化 | 無効 | 機能全体のオプトインスイッチ |
| Wikiフォルダ | `Second Brain` | 生成ノートのルートフォルダ |
| スケジューラを有効化 | 無効 | 間隔が経過していれば、アプリ起動時に非破壊的なクリーンアップパイプラインを自動実行 |
| スケジューラ間隔（時間） | 24 | 自動実行間の最小時間（最小1） |

#### 思考ツール（読み取り専用 — ノートを作成しません）

| ツール | 動作 | LLM呼び出し |
|--------|------|------------|
| challenge | 過去のノートを根拠に、現在の主張の穴や反例を指摘する | 1回 |
| connect | 2つのトピックを横断検索して接続アイデアを導き出す | 1回 |
| emerge | 直近N日のノートから、まだ名前が付いていないパターンを見つける（最新60件が上限。超過時は通知） | 1回 |
| reconcile | ノート間の矛盾を点検してレポートを返す（ノートは変更しません） | 1回 |

#### 生成ツール（ノートを作成・更新します）

| ツール | 動作 | LLM呼び出し |
|--------|------|------------|
| synthesize | トピックに関連するノートを統合してWikiノートを生成・更新する | 1回 |
| architect | コードベース構造の分析ノートを生成する（モジュール骨格は400行が上限） | 3回（overview / modules / decisions で各1回） |
| create_wiki_note | Wikiフォルダ配下にノートを作成する | 0回（書き込みのみ） |
| update_index | Wikiフォルダの `index.md` カタログを更新する | 0回（書き込みのみ） |

`architect` はボルトのファイル一覧を直接走査し、`update_index` はWikiフォルダのマークダウンファイルを直接読み取ります。この2つは埋め込みインデックスを使いません。

#### Sentinelブロック — あなたのメモは上書きされません

生成された領域は `<!-- @generated:KEY -->` から `<!-- @end:KEY -->` までのマーカーで囲まれます。再生成時に置き換わるのはこのブロックの中だけなので、同じノートにあなたが書き足したメモはそのまま残ります（べき等な更新）。LLMの出力にマーカーらしき文字列が混ざっていた場合は無害化されます。

#### 安全装置

- Wikiフォルダの外への書き込みをブロックします（`..`、絶対パス、ドライブレターを拒否）
- 破壊的ツールの実行前に確認モーダルを表示できます（設定で有効化）
- インデックスが古い状態で結果を生成した場合、警告文を付け加えます

#### スケジューラ（Cleanup_Pipeline）

タイマーで動くのではなく、**Obsidianを起動したとき**に、最終実行から設定した間隔（デフォルト24時間）が過ぎているかを確認して実行します。LLM呼び出しは0回で、4つの段階を順に処理します。

1. フォルダの存在を保証する
2. `index.md` カタログを更新する
3. ナレッジギャップレポートを生成する
4. 活動ログを追記する

ある段階の失敗は隔離され、残りの段階は続行されます。すべての段階が失敗した場合は最終実行時刻を更新しないため、次のトリガーで再試行されます。コマンドパレットの「Second Brain 정리 실행 (스케줄러)」から手動で実行することもできます。

### 累積学習

セッションをまたいで知識が積み上がるようにするための機能群です。

#### 振り返りチェーン（LLM呼び出しの増加なし）

日次振り返りの生成時に、直近7日間の振り返りセクションを一緒に入力します。これにより、繰り返し現れる問題とその改善状況を追跡できます。入力するのは日次ノート全体ではなく振り返りセクションのみ（1件あたり1000文字）です。過去の振り返りがない場合は、従来と同じ動作になります。

#### 会話結論の収穫（収穫1回につきLLM 1回）

チャットセッションは50件が上限で、古いものは静かに消えます。残す価値のある結論はノートに移します。

1. セッション一覧を開き、収穫ボタン（新芽アイコン）をクリック
2. 結論・決定・根拠・未解決の質問だけが抽出されます
3. `{Wikiフォルダ}/Conversations/YYYY-MM-DD タイトル.md` として保存されます

元の会話は保存しません（雑談や試行錯誤が検索の根拠になるのを避けるためです）。保存されたノートは自動的にインデックスされ、以降の検索で根拠として使われます。手動トリガーのみで、Second Brainの有効化が必要です。

#### ナレッジギャップレポート（LLM呼び出し0回）

インデックスのデータから構造的な空白をローカルで計算します。4つの指標を見ます。

| 指標 | 意味 |
|------|------|
| 参照されているが存在しないノート | 複数の場所からリンクされているのに、まだ作成されていない |
| 参照されているが内容が薄いノート | バックリンクがあるが、本文が200文字未満 |
| どこにも接続されていないノート | 双方向ともリンクがなく、グラフ探索で到達できない |
| 片方向にしか接続されていないノート | リンクが一方向のみ |

上位20件を `{Wikiフォルダ}/Knowledge Gaps.md` にsentinelブロックで記録します。自動修正は行わず、「見る場所」を提示するだけです。スケジューラのパイプラインに含まれるほか、コマンドパレットの「지식 공백 리포트 갱신」から手動でも実行できます。

#### 復習キュー（LLM呼び出し0回）

長く開いていないが接続が多いノートを5件提示します。コマンドパレットの「복습 큐 (다시 볼 노트)」から実行します。

- スコアは経過日数とリンク数から計算します
- 本文が200文字未満のノートと、直近7日以内に提示済みのノートは除外します
- ノートに評価用のフィールドを埋め込みません。閲覧履歴はプラグイン設定にのみ保存します
- 導入直後でアクセス履歴がない場合は、ノートの更新時刻にフォールバックします
- 削除・移動されたノートは履歴から整理されます
