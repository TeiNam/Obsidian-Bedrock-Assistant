### Graph RAG ボルト検索

埋め込み（ベクトル）とノート間リンクを組み合わせた読み取りレイヤーです。ノートの作成・変更は一切行いません。

**動作の流れ**

1. **チャンク分割** — ノートを既定2000文字・重複200文字で分割し、チャンクごとに埋め込みを生成します。
2. **ベクトル検索** — クエリの埋め込みと比較して、起点（シード）となるノートを選びます。
3. **グラフ探索** — シードのリンク（発リンク・被リンク）をたどって近隣ノートまで候補を広げます。探索の深さ（hop）は0〜3で、既定は1です。0にすると探索は行われません。
4. **スコア統合** — 各候補の関連性にグラフ距離の減衰を掛け合わせます。

**スコアの決まり方**

- 統合スコア = **関連性 × 0.5^hop**（加算ではなく乗算）。シード（hop 0）は減衰係数が1.0なので関連性そのままで、値は0.0〜1.0に収まります。
- 近隣ノートの関連性は「近隣自身のベクトル類似度 × 0.6 + シードの類似度 × 0.4」です。近隣自身の埋め込みが使えない場合（未埋め込み・次元不一致）はシードの類似度のみを使います。
- 類似度の正規化は `(コサイン + 1) / 2` なので、**無関係（コサイン0）が0.5に写ります**。閾値が無いと無関係なノートが「関連度50%」として並ぶため、関連性が**0.55未満の候補は除外**します。
- この0.55の判定は、**減衰を適用する前の関連性**に対して行います。減衰後の統合スコアで判定すると、hop 1の近隣の理論上の最大値（1.0 × 0.5 = 0.5）が閾値を下回り、グラフ近隣が全て消えて純粋なベクトル検索に退化するためです。

**インデックスの整合性**

- インデックスには埋め込み構成の署名（`{provider}:{model}`）と次元数が保存されます。構成の変更を検出すると古いベクトルを破棄し、キーワード検索にフォールバックしたうえで再インデックスを案内します。
- 次元が一致しないノートは「比較不可」として扱われます（以前は類似度0 → 正規化0.5 → 全ノートが同点 → アルファベット順という誤った結果になっていました）。
- **ハイブリッド検索**: ベクトル検索と並行してキーワード検索を実行し、2つの順位を相互順位融合（RRF、`k = 60`）で統合します。キーワード側の重みはベクトル側の半分です — このプラグインの主信号は埋め込みであり、重みを同じにすると、ある語を繰り返しているだけのノートが実際に答えを持つノートを押し出します。代わりにキーワード検索だけが見つけた候補に結果枠を2つ予約し、エラーコード・関数名・バージョン文字列のように完全一致が必要な検索が埋め込み類似度に埋もれないようにしています。
- **一致した本文**: 検索結果にはノートの冒頭ではなく、**実際に一致したチャンクの本文**（最大2,000文字）が入ります。ノート後半の一節が一致して浮上した結果に対し、先頭500文字を抜粋して渡すと、モデルはそのノートが見つかった理由そのものを見られません。
- **増分インデックス**: ファイルの作成・変更・リネーム・削除を反映します。2秒のデバウンスの後、同時に2件まで処理しますが、**同じパスの連続イベントは順序を保ちます** — 作成直後の削除が逆順で適用されると、消したノートが検索に残ります。フォルダ移動のように多数のファイルが一度に変わっても、埋め込みAPIへのリクエストが一斉に集中することはありません。

埋め込みシグネチャは`{プロバイダー}:{モデルID}`の形式です。例: `bedrock:amazon.titan-embed-text-v2:0`、`openai:text-embedding-3-large`、`ollama:nomic-embed-text`、`gemini:text-embedding-004`

**設定**（設定 → Agent LLMs → Graph RAG 検索）

| 項目 | 既定値 | 説明 |
|------|--------|------|
| グラフ探索の深さ | 1 | リンクをたどるhop数（0〜3、0で探索を無効化） |
| チャンク最大サイズ | 2000 | 単一チャンクの最大文字数（最小1） |
| チャンク重複サイズ | 200 | 隣接チャンク間の重複文字数（チャンク最大サイズより小さい値） |

**LLM呼び出し**: 検索1回につき、クエリの埋め込み生成が1回だけ発生します（チャット用モデルの呼び出しは0回）。近隣の類似度はインデックス済みのベクトルから計算するため、追加のAPI呼び出しは発生しません。インデックス作成時はチャンクごとに埋め込みを生成します。

### Second Brain レイヤー（LLM Wiki）

Graph RAGの「読み取り」の上に「書き込み」を載せたレイヤーです。**オプトイン機能で、既定はオフ**です。

> オフの間は、このレイヤーによってノートが自動的に作成・変更・削除されることは一切ありません。有効化しても、下記の「思考ツール」はノートを作りません。

**設定**（設定 → Agent LLMs → Second Brain）

| 項目 | 既定値 | 説明 |
|------|--------|------|
| Second Brain 有効化 | オフ | 能動的なナレッジレイヤーの有効・無効 |
| Wikiフォルダ | `Second Brain` | 生成ノートを作成・管理するルートフォルダ |
| スケジューラ有効化 | オフ | 間隔が経過していれば、Obsidian起動時に非破壊的な整理パイプラインを実行 |
| スケジューラ間隔（時間） | 24 | 自動実行の最小間隔（最小1） |

#### 思考ツール（読み取り専用 — ノートを作りません）

| ツール | 動作 | LLM呼び出し |
|--------|------|-------------|
| `challenge` | 過去のノートを根拠に、いま立てている主張の穴・反例を指摘する | 1回（検索の埋め込み1回） |
| `connect` | 2つのトピックを横断検索し、両者をつなぐ着想を出す | 1回（検索の埋め込み2回） |
| `emerge` | 直近N日のノートから、まだ名前が付いていないパターンを見つける | 1回（検索を使わずインデックス全体から抽出） |
| `reconcile_topic` | ノート間の矛盾を点検してレポートする（ノートは変更しません） | 1回（検索の埋め込み1回） |

`emerge` は対象を最新60件までに制限します。それを超える場合は「何件のうち何件を分析したか」を結果に明記するため、黙って一部が落ちることはありません。

#### 生成ツール（ノートを作成・更新します）

| ツール | 動作 | LLM呼び出し |
|--------|------|-------------|
| `synthesize_topic` | トピックに関連するノートを総合してWikiノートを生成・更新する | 1回（検索の埋め込み1回） |
| `architect` | コードベースの構造を分析したノートを作る（モジュール骨格は400行が上限） | 3回（overview / modules / decisions の各セクション1回） |
| `create_wiki_note` | 指定した題名・本文でWikiノートを作る | 0回 |
| `update_index` | Wikiフォルダのノートを集めて `index.md` のカタログを更新する | 0回 |

> `architect` と `update_index` はボルトのファイル一覧を直接読むため、Graph RAGインデックスを必要としません。それ以外のツール（`synthesize_topic`・`challenge`・`connect`・`reconcile_topic`・`emerge`）はインデックスを参照するので、先にボルトインデックスを作成してください。

#### Sentinelブロック（ノートを上書きしない仕組み）

生成された領域は `<!-- @generated:KEY -->` 〜 `<!-- @end:KEY -->` のマーカーで囲まれます。

- 再生成時に置き換わるのは**このブロックの内部だけ**です。同じノートに自分で書いたメモはそのまま残ります（べき等な更新）。
- LLMの出力にマーカーと同じ文字列が混ざっていた場合は無害化されるため、生成物がブロックの境界を壊すことはできません。

現在使われているブロックキー: `synthesis`（主題の統合）、`overview`/`modules`/`decisions`（アーキテクチャ）、`catalog`（Wikiインデックス）、`knowledge-gaps`（ギャップレポート）、`reconcile`（矛盾レビュー）、`related-links`（リンク提案）、`canonical-candidates`（重複候補）、`decisions`（決定台帳）。

#### 安全装置

- Wikiフォルダの外への書き込みを拒否します（`..`・絶対パス・ドライブレターは拒否）。
- ノートを作成・編集・削除・移動するツールの実行前に確認モーダルを表示できます（設定 → Agent LLMs → 対話 → 「ノート変更の確認」）。
- インデックスが古い状態で結果を生成した場合は、その旨の警告文を結果に添えます。

#### スケジューラ（整理パイプライン）

**タイマーによる定期実行ではありません。** Obsidianを起動したときに、前回の実行から設定した間隔（既定24時間）が経過しているかを確認し、経過していれば実行します。起動しなければ実行されません。

自動実行されるのは非破壊的な5段階だけです。

| 段階 | 内容 |
|------|------|
| 1 | Wikiフォルダの存在を保証 |
| 2 | `index.md` のカタログを更新 |
| 3 | ナレッジギャップレポートを更新 |
| 4 | Basesダッシュボードを更新（生成マーカーのないファイルは上書きしない） |
| 5 | 活動ログに1行を追記 |

段階ごとの失敗は隔離され、残りの段階はそのまま続行します。すべての段階が失敗した場合は最終実行時刻を更新しないため、次の起動時に再試行されます。

#### 実行方法

各ツールはチャットからAIに依頼するか、コマンドパレットから直接実行できます。

| 機能 | コマンド名 |
|------|----------------------|
| 主題の総合 | `トピックを統合 (synthesize)` |
| 矛盾の点検 | `矛盾をチェック (reconcile)` |
| 主張への反論 | `主張に反論 (challenge)` |
| 2つの主題を接続 | `2つのトピックを接続 (connect)` |
| 最近のパターン発見 | `最近のパターンを発見 (emerge)` |
| コードベースアーキテクト | `コードベースアーキテクト (architect)` |
| ナレッジギャップレポートの更新 | `知識ギャップレポートを更新` |
| 復習キュー | `復習キュー (見直すノート)` |
| 整理パイプラインの手動実行 | `Second Brain整理を実行 (スケジューラ)` |
| 矛盾のレビューと反映 | `矛盾をレビューして反映 (reconcile → apply)` |
| リンク提案 | `リンク提案 (孤立・スタブノートの接続)` |
| 重複候補のレビュー | `重複候補をレビュー (正本・エイリアス整理)` |
| 決定の抽出 | `決定を抽出 → 台帳 (decisions)` |

| Basesダッシュボード | `Agent LLMsダッシュボードを更新して開く` |
| AI変更履歴 | `AI変更履歴を開く` |
| 直前のAI変更を取り消す | `最後のAI変更を元に戻す` |

### 承認式の整理

5つのコマンドは変更案を提示して止まります。項目ごとにチェックするリストが開き、承認するまで何も書き込みません。承認した内容もsentinelブロックの中に入るため、同じファイルに自分で書いた文章は残ります。

| コマンド | 何を提案するか | 反映時のLLM呼び出し |
|----------|----------------|---------------------|
| 矛盾をレビューして反映 (reconcile → apply) | 1つのトピックのノート間で食い違う記述の訂正案 | 0 — 点検は済んでいます |
| リンク提案 (孤立・スタブノートの接続) | 孤立・スタブノートから関連ノートへのリンク | 0 |
| 重複候補をレビュー (正本・エイリアス整理) | 同じ対象を扱うノートの正本とエイリアス | 0 |
| 決定を抽出 → 台帳 (decisions) | 理由・担当・期限・根拠が付いた決定 | 0 — 抽出は済んでいます |
| Inbox整理 (タイトル・移動・タグの提案) | 新しく取り込んだノートのタイトル・移動先フォルダ・タグ | 0 — 提案は済んでいます |

**リンク提案**は類似度0.82以上を候補とし、ノートごとに最大3件を提案します。承認したリンクは`related-links`ブロックに追記され、再実行するとそのブロックを置き換えるので重複は積み上がりません。

**重複候補**は類似度0.9以上、1クラスタ最大8件です。**何も削除も統合もしません。** 正本ノートのフロントマターに`aliases`を入れ、`canonical-candidates`ブロックに残りを列挙するだけなので、統合するかどうか（あるいは「重複ではなかった」と判断するか）は利用者が決めます。

**決定台帳**は`{Wikiフォルダ}/Decisions.md`です。マージでは自分で編集した値を保持し、空欄だけを埋めますが、ステータスは例外です — `open` → `done` → `superseded` の方向にのみ進み、戻りません。置き換えられた決定は削除せず印を付けます。かつて別の判断をしたという事実そのものに、残す価値があるからです。

**Inbox整理**は1回で最大12件のノートを扱います。リネームはObsidianのリンク保存APIを通すため、旧名を指していたリンクがファイルに追従します。移動先の名前が既に存在する場合は移動をスキップし、タグは適用します。

**コスト:** 反映はいずれもLLM呼び出し0回です。提案の生成側は、矛盾・決定・Inbox整理がそれぞれ1回、リンク提案と重複候補は0回です（インデックスに保存された埋め込みだけを使います）。

### 引用チェック

回答がノートを引用すると、そのパスをインデックスと、`#見出し`アンカーをそのノートの見出し一覧と照合します。確認できなかった引用は回答の下に列挙されます。

- パスはObsidianがリンクを解決する方式と同じく**パスの接尾一致**で判定します — `Projects/Note`の引用は`Archive/Projects/Note.md`に一致します。
- コードスパンとコードブロックはスキップします。例の中のパスを引用として数えません。
- 外部リンク（URIスキームがあるもの、プロトコル相対URL、フラグメントのみのもの）は無視します。
- 復元したメッセージにも検証が走ります。サイドバーを開き直しても、保存したセッションを読み込んでも同じ警告が見えます。

モデルがもっともらしいパスを作り出す、という特定の失敗を捕まえるための仕組みです。回答自体はそのまま表示し、印を付けるだけです。

**コスト:** LLM呼び出し0回、埋め込み呼び出し0回。

### ノートリンクの表記

プラグインが書くリンクはすべて1つの関数を通ります。書く場所が複数あっても規則は同じです。

- リンク先は拡張子を除いた**パス**で、ノートのタイトルはエイリアスとして付きます: `[[パス/ノート|タイトル]]`。タイトルをリンク先には使いません — ノートのタイトルは本文の最初の`# H1`から来るもので、ファイル名と異なることがよくあります。
- Wikiリンクの中では`#`と`|`をエスケープする方法がありません。`#`はアンカーを開始し、最初の`|`はエイリアスを開始します。パスやエイリアスにこの文字がある場合は、パーセントエンコードしたMarkdownリンクにフォールバックします。Obsidianは両方の形式を同じように解釈します。
- アンカーリンクは見出しをアンカーとして使える場合にのみ書きます。そうでなければノート全体を指す引用にフォールバックします。

### フロントマタープロパティ検索

フォルダ・タグ・期間のほかに、フロントマターの任意のプロパティで検索を絞り込めます。

| 演算子 | 意味 |
|--------|------|
| `=` / `!=` | 等しい / 等しくない |
| `>` `>=` `<` `<=` | 数値・日付の比較 |
| `~` | 部分一致 |

ドット記法で入れ子のキーにも届きます — `project.status = active` は `project: { status: active }` に一致します。

不正な条件は**破棄せず通知します。** モデルが `modifiedAfter: "先月"` のように渡したとき、条件が無視されたままボルト全体の結果を受け取ると、モデルも利用者も条件が適用されなかった事実に気づけません。

日付は**ローカル時刻**で解釈します。`new Date("2026-09-01")` はUTC深夜なのでJSTでは9月1日09:00になり、その朝に書いたノートが「9月1日以降」の条件から漏れます。インデックスの更新時刻はローカルのファイル時刻なので、こちらも合わせています。

**コスト:** LLM・埋め込み呼び出しなし — インデックスのデータだけを使います。

### AI変更履歴と安全な取り消し

ノートを変更したAI操作ごとに、変更前後のスナップショットを記録します。直近20件を保持します。

- **取り消しは、その後に利用者が触っていないファイルのみ復元します。** 触っていれば上書きせずスキップします — 利用者の編集が取り消しによって失われることはありません。
- 作成・変更・削除されたパスをすべて含み、フォルダも対象です。
- 復元前にパスを検査します。絶対パス、`..` による脱出、空のセグメントは拒否します。
- 履歴はボルトではなくプラグインフォルダに保存されます。

**AI変更履歴を開く**で一覧を表示し、**最後のAI変更を元に戻す**で直前の操作を取り消します。

**コスト:** LLM呼び出し0回、埋め込み呼び出し0回。

### 添付ファイルRAG

ボルト内の `.txt`・`.csv`・`.json`・`.html` ファイルをチャンクとしてインデックスし、ノートと一緒に検索します。会話1回で読んで破棄する方式ではありません。

ノートと同じパイプラインを通ります — チャンク埋め込み、キーワード統合、リンクがあればグラフ探索まで。再インデックスも同じファイルイベントに従います。

### 出典チャンクのハッシュ・「古い」印・再生成diff

統合ノートは出典パスだけでなく、**出典チャンクごとの内容ハッシュ**を記録します。

- 出典の内容が変わるとハッシュが合わなくなり、ノートに「古い」印が付きます。パスが残っているだけでは統合が最新だとは言えません。
- 再生成時に何が変わったかを**diff**(最大40行)で示します。更新が実質的かどうかを見てから受け入れられます。
- 出典の記録は `synthesis-provenance` というsentinelブロックに入ります。再生成ではそのブロックだけが置き換わり、利用者が書いた文章は残ります。

### Basesダッシュボード

ボルトのデータから4つのビューを持つ `.base` ファイルを生成します。

| ビュー | 内容 |
|--------|------|
| 決定台帳 | ステータス・担当・期限が付いた決定 |
| 未解決の質問 | 記録されたがまだ答えのない質問 |
| 古い知識 | 統合の後に出典が変わったノート |
| 復習キュー | リンクは多いが長く開いていないノート |

**Agent LLMsダッシュボードを更新して開く**コマンドで実行するか、スケジューラのパイプラインが更新します。

- 生成ファイルにはマーカーが付きます。**マーカーのないファイルは決して上書きしません** — 利用者が書いたファイルとパスが衝突する場合は、黙って消すのではなく失敗を通知します。
- 消えた投影は**削除せず無効化**します(`dashboard_active: false`)。生成ファイルに利用者がメモを加えていても残ります。

**コスト:** LLM呼び出し0回、埋め込み呼び出し0回。

### 累積学習

使うほど手元の文脈が積み上がる機能群です。

#### 振り返りチェーン（LLM呼び出しの増加なし）

日次振り返りを生成するとき、直近7日分の振り返りセクションを一緒に入力します。これにより、繰り返している問題と、それが改善したかどうかを追跡できます。

- 日次ノート全体ではなく、**振り返りセクションだけ**（1件あたり最大1000文字）を渡します。
- 過去の振り返りが無い場合は、従来と同じ動作になります。
- LLM呼び出しは日次振り返り1回につき1回のままで、追加の呼び出しは発生しません。
- 実行はチャットからです。入力欄に「회고」「retrospective」「振り返り」などのキーワードを単独で入力すると、AIへの送信前に処理が差し込まれます。

#### 会話の結論収穫（収穫1回につきLLM 1回）

チャットセッションは50件を上限に管理されるため、古いものは黙って消えていきます。結論を残したいセッションは収穫してください。

1. チャットヘッダーの履歴アイコンからセッション一覧を開きます。
2. 残したいセッションの**収穫ボタン（芽のアイコン）**をクリックします。
3. 結論・決定・根拠・未解決の問いだけが抽出され、`{Wikiフォルダ}/Conversations/YYYY-MM-DD タイトル.md` として保存されます。

- 元の会話は保存しません。雑談や試行錯誤が検索の根拠になるのを避けるためです。
- 保存されたノートは自動的にインデックスされ、以降の検索の根拠になります。
- 手動トリガーのみで、自動では実行されません。Second Brainの有効化が必要です。

#### ナレッジギャップレポート（LLM呼び出し0回）

インデックスにあるデータだけで構造的な欠けをローカル計算します。埋め込みもLLMも使いません。

| 指標 | 内容 |
|------|------|
| 参照されているのに存在しないノート | 複数の場所からリンクされているが、まだ作られていない |
| 参照はあるが中身が薄いノート | 被リンクがあり、本文が200文字未満 |
| どこにもつながっていないノート | 発リンク・被リンクの両方が無い（グラフ探索で到達できない） |
| 片方向にしかつながっていないノート | A→Bはあるが、戻る参照が無い |

上位20件を `{Wikiフォルダ}/Knowledge Gaps.md` にSentinelブロックとして記録します。**自動修正は行わず、「見るべき場所」だけを提示します。** スケジューラのパイプラインに含まれるほか、コマンド `知識ギャップレポートを更新` で手動更新もできます。

#### 復習キュー（LLM呼び出し0回）

長く開いていないが、リンクが多いノートを5件だけ提示します。コマンドは `復習キュー (見直すノート)` です。

- スコアは「経過日数 + リンク数」で計算します。
- 本文200文字未満のノートと、直近7日以内にすでに提示したノートは除外します。
- ノートに評価用のフィールドを埋め込むことはありません。閲覧履歴はプラグインの設定内にのみ保存されます。
- アクセス履歴が無い導入直後は、ノートの更新時刻にフォールバックします。
- 削除・移動されたノートは履歴から整理されます。
