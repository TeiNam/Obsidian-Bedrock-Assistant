# Graph RAG & Second Brain

[← 돌아가기: README-KR.md](../README-KR.md)

[English](second-brain-en.md) | [한국어](second-brain-kr.md) | [日本語](second-brain-ja.md)

이 문서는 볼트 검색(Graph RAG)과 지식 쓰기(Second Brain) 계층을 상세히 다룹니다. 설치와 기본 사용법은 README를 참고하세요.

> 커맨드 팔레트의 표시 이름은 현재 한국어로만 등록되어 있습니다.
### Graph RAG 검색

노트를 청크로 나눠 임베딩하고, 검색된 노트의 링크를 따라 이웃 노트까지 후보에 포함하는 검색 계층입니다.

동작 순서:

1. **청크 임베딩** — 노트를 기본 2000자(겹침 200자) 단위로 분할해 청크마다 임베딩을 생성합니다.
2. **벡터 검색** — 쿼리 임베딩과 비교해 시드 노트를 뽑습니다.
3. **그래프 순회** — 시드 노트의 아웃링크·백링크를 따라 이웃을 확장합니다. 탐색 깊이는 0~3(기본 1)이며, 0이면 순회를 하지 않고 시드만 사용합니다.
4. **통합 점수** — 관련성(0.0~1.0으로 정규화한 벡터 유사도)에 그래프 거리 감쇠를 **곱합니다**. 감쇠 가중치는 `0.5^hop`이라 hop이 1 늘어날 때마다 절반이 되고, 결과도 0.0~1.0 범위입니다. 이웃 노트의 관련성은 "이웃 자신의 유사도 60% + 시드 유사도 40%"의 가중 평균입니다.
5. **최소 관련성 필터** — 감쇠를 적용하기 **전의** 관련성이 0.55 미만인 후보를 제외합니다. 감쇠 후 점수에 적용하면 hop 1 이웃의 이론적 최대값(1.0 × 0.5 = 0.5)이 임계값보다 낮아 그래프 이웃이 전부 탈락하기 때문입니다. 이 필터로 후보가 하나도 남지 않으면 키워드 검색으로 폴백합니다.

임베딩 시그니처는 `{프로바이더}:{모델 ID}` 형태입니다. 예: `bedrock:amazon.titan-embed-text-v2:0`, `openai:text-embedding-3-large`, `ollama:nomic-embed-text`, `gemini:text-embedding-004`

설정 → **Graph RAG 검색**:

| 설정 | 기본값 | 설명 |
|------|--------|------|
| 그래프 순회 깊이 | 1 | 링크를 따라 확장할 hop 수 (0~3, 0이면 순회 비활성) |
| 청크 최대 크기 | 2000 | 단일 청크의 최대 글자 수 |
| 청크 겹침 크기 | 200 | 인접 청크 간 겹침 글자 수 (청크 최대 크기보다 작아야 함) |

**증분 인덱싱** — 파일 생성·수정·이름변경·삭제 이벤트를 반영합니다. 각 파일은 2초 디바운스 후 직렬 큐(동시성 1)로 처리되므로, 폴더 이동처럼 여러 파일이 한꺼번에 바뀌어도 임베딩 요청이 병렬로 몰리지 않습니다.

**임베딩 모델 변경 감지** — 인덱스에 `{백엔드}:{모델}` 시그니처와 벡터 차원을 함께 저장합니다. 임베딩 모델이나 백엔드를 바꾸면 기존 벡터를 폐기하고 키워드 검색으로 폴백하며, 재인덱싱이 필요하다는 안내를 표시합니다. 차원이 다른 벡터는 유사도 0이 아니라 "비교 불가"로 처리합니다. 일부만 불일치하는 경우(재인덱싱 진행 중 등)에는 비교 가능한 후보로 검색을 계속하면서 인덱스가 낡았음을 함께 알립니다.

### Second Brain Layer (옵트인)

Graph RAG의 "읽기" 위에 노트 생성·갱신을 올린 계층입니다.

> **기본값은 꺼져 있습니다.** 설정 → Agent LLMs → **Second Brain** → "Second Brain 활성화"를 켜기 전에는 이 계층이 어떤 노트도 자동으로 생성·수정·삭제하지 않습니다. 활성화 전에는 관련 커맨드와 도구가 안내 메시지만 반환하며, LLM 호출도 하지 않습니다.

#### 사고 도구 (노트를 만들지 않음)

읽기 전용 도구입니다. 볼트를 검색해 결과를 채팅에 보여주기만 하고, 어떤 노트도 생성·수정하지 않습니다.

| 도구 | 커맨드 | 하는 일 | LLM 호출 |
|------|--------|---------|----------|
| `challenge` | 주장 반박 (challenge) | 과거 노트를 근거로 현재 주장의 허점·반례·전제를 검토 | 1회 |
| `connect` | 두 주제 연결 (connect) | 두 주제를 각각 검색해 교차 컨텍스트로 묶고 연결 아이디어 도출 | 1회 |
| `emerge` | 최근 패턴 발견 (emerge) | 최근 N일 노트에서 아직 이름 붙지 않은 패턴 발견 | 1회 |
| `reconcile_topic` | 모순 점검 (reconcile) | 노트 간 상충하는 진술을 점검해 리포트로 제시 (노트 미변경) | 1회 |

`emerge`는 프롬프트에 넣는 노트를 최신 60건으로 제한하고, 초과분이 있으면 몇 건 중 60건만 분석했는지 함께 알립니다.

#### 생성 도구 (노트를 만듦)

| 도구 | 커맨드 | 하는 일 | LLM 호출 |
|------|--------|---------|----------|
| `synthesize_topic` | 주제 종합 (synthesize) | 주제 관련 노트를 검색해 종합 노트를 생성/갱신 | 1회 |
| `architect` | 코드베이스 아키텍트 (architect) | 코드베이스 구조를 스캔해 `Architecture.md`의 overview/modules/decisions 섹션 작성 | 3회 (섹션당 1회) |
| `create_wiki_note` | 위키 노트 생성 | 제목·본문을 받아 프론트매터 + `## For future AI` 프리앰블 규격 노트 생성 | 0회 |
| `update_index` | 위키 인덱스 갱신 | 위키 폴더 노트를 모아 `index.md` 카탈로그 갱신 | 0회 |

`synthesize_topic`은 검색 결과가 없으면 노트를 만들지 않고 안내만 반환합니다. `architect`는 볼트 파일 목록을 직접 읽고 모듈 골격을 400줄까지만 프롬프트에 넣으며, `update_index`도 볼트의 마크다운 파일을 직접 훑습니다. 즉 이 두 도구는 Graph RAG 인덱스를 사용하지 않습니다.

#### Sentinel 블록 — 내가 적은 메모는 보존됩니다

생성 도구는 만든 영역을 마커로 감쌉니다.

```markdown
<!-- @generated:synthesis -->
(AI가 생성한 내용)
<!-- @end:synthesis -->

여기에 직접 적은 메모는 재생성해도 그대로 남습니다.
```

재실행하면 해당 블록 **안쪽만** 교체하므로, 같은 노트에 직접 적어둔 메모·프론트매터·프리앰블은 그대로 남습니다(멱등 갱신). LLM 응답에 마커 문자열이 섞여 들어오면 블록 구조가 깨지지 않도록 무해화합니다.

블록 키는 기능별로 나뉩니다: `synthesis`(주제 종합), `overview`/`modules`/`decisions`(아키텍처), `catalog`(위키 인덱스), `knowledge-gaps`(지식 공백 리포트).

#### 그 밖의 안전 장치

- **위키 폴더 밖 쓰기 차단** — 경로에 `..`, 절대경로, 드라이브 문자가 포함되면 거부합니다.
- **덮어쓰기 금지** — `create_wiki_note`와 대화 결론 수확은 같은 경로에 파일이 이미 있으면 덮어쓰지 않고 실패로 보고합니다.
- **파괴적 도구 확인** — 설정 → Agent LLMs → 대화 → "노트 변경 확인"을 켜면 노트를 생성·수정하는 도구(`create_wiki_note`, `update_index`, `synthesize_topic`, `architect` 포함) 실행 전에 확인 대화상자를 표시합니다.
- **낡은 인덱스 경고** — 임베딩 구성이 바뀐 상태에서 결과를 만들면 결과 메시지에 경고 문구를 덧붙입니다.

#### 설정

설정 → **Second Brain**:

| 설정 | 기본값 | 설명 |
|------|--------|------|
| Second Brain 활성화 | 꺼짐 | 이 계층 전체의 옵트인 스위치 |
| 위키 폴더 | `Second Brain` | 생성 노트의 루트 폴더. 하위에 `entities`, `concepts`, `projects` 폴더를 만듭니다 |
| 스케줄러 활성화 | 꺼짐 | 주기가 지났으면 Obsidian 시작 시 정리 파이프라인 자동 실행 |
| 스케줄러 주기 (시간) | 24 | 자동 실행 간 최소 시간 (최소 1) |

#### 스케줄러 (정리 파이프라인)

상시 타이머가 아닙니다. **Obsidian을 시작할 때** 마지막 실행에서 설정 주기(기본 24시간)가 지났는지 확인해 실행합니다. 커맨드 **"Second Brain 정리 실행 (스케줄러)"** 로 즉시 실행할 수도 있습니다. 노트를 덮어쓰는 작업(종합·모순 반영 등)은 파이프라인에 포함되지 않습니다. **LLM 호출 0회.**

1. 위키 폴더와 카테고리 폴더 보장 (없으면 생성, 있으면 유지)
2. `index.md` 카탈로그 갱신 (`catalog` 블록만 교체)
3. 지식 공백 리포트 갱신
4. `log.md`에 실행 이력 한 줄 append (기존 로그는 변경하지 않음)

한 단계가 실패해도 나머지 단계는 계속 실행됩니다. 모든 단계가 실패하면 마지막 실행 시각을 갱신하지 않으므로 다음 트리거에서 다시 시도합니다.

### 지식 공백 리포트

인덱스 데이터로 구조적 공백을 로컬 계산합니다. **LLM 호출 0회.** 커맨드 **"지식 공백 리포트 갱신"** 또는 스케줄러 파이프라인으로 실행합니다.

네 가지 지표:

| 지표 | 판정 기준 |
|------|-----------|
| 참조되지만 없는 노트 | 다른 노트가 링크하는데 아직 존재하지 않음 |
| 참조는 받는데 내용이 부족한 노트 | 백링크가 있고 본문이 200자 미만 |
| 어디에도 연결되지 않은 노트 | 아웃링크·백링크 모두 없음 (그래프 순회로 도달 불가) |
| 한 방향으로만 연결된 노트 | 링크가 한쪽 방향만 존재 |

상위 20건을 `{위키 폴더}/Knowledge Gaps.md`에 sentinel 블록으로 기록합니다. 자동 수정은 하지 않고 "볼 곳"만 위키링크로 제시하므로, 아직 없는 노트는 클릭해서 바로 만들 수 있습니다. 위키 폴더 하위의 생성 노트는 집계에서 제외됩니다.

### 복습 큐

오래 열지 않았지만 연결이 많은 노트 5건을 제시합니다. **LLM 호출 0회.** 커맨드 **"복습 큐 (다시 볼 노트)"**.

- 점수 = 경과 일수 점수 + 링크 수 점수
- 본문 200자 미만 노트는 제외합니다 (빈 노트는 지식 공백 리포트가 다룹니다)
- 최근 7일 내에 이미 제시한 노트는 제외해 며칠 연속 같은 노트가 나오지 않게 합니다
- 노트에 등급 필드를 심지 않습니다. 열람 이력은 플러그인 설정에만 저장합니다
- 접근 이력이 없는 도입 초기에는 노트 수정 시각으로 폴백합니다
- 삭제·이동된 노트는 이력에서 정리됩니다

### 대화 결론 수확

지난 대화 목록에서 새싹 아이콘을 누르면 그 대화의 결론·결정·근거·미해결 질문만 추출해 `{위키 폴더}/Conversations/YYYY-MM-DD 제목.md`로 저장합니다. **수확 1회당 LLM 1회.** Second Brain 활성화가 필요합니다.

대화 세션은 최대 50개까지만 보관되므로 오래된 것은 조용히 사라집니다. 남길 가치가 있는 결론은 노트로 옮겨두면 인덱싱되어 이후 검색 근거가 됩니다.

원본 대화는 노트에 넣지 않습니다. 잡담과 시행착오까지 검색 근거가 되면 이후 검색 품질이 떨어지기 때문입니다. 자동 실행은 없고 수동 트리거만 제공하며, 같은 이름의 노트가 이미 있으면 덮어쓰지 않습니다.

### 회고 체인

일일 회고는 채팅에 **"회고" / "retrospective" / "振り返り"** 를 입력하면 생성됩니다(전용 버튼은 없습니다). 이때 최근 7일의 회고 섹션을 함께 입력해 반복되는 문제와 개선 여부를 추적합니다. **LLM 호출은 늘어나지 않습니다** (기존과 동일하게 회고 생성 1회).

일일 노트 전체가 아니라 회고 섹션만, 건당 1000자까지 넣습니다. 과거 회고가 없으면 기존과 동일하게 당일 입력만으로 동작합니다.
