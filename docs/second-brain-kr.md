# Graph RAG & Second Brain

이 문서는 볼트 검색(Graph RAG)과 지식 쓰기(Second Brain) 계층을 상세히 다룹니다. 설치와 기본 사용법은 README를 참고하세요.

> 커맨드 팔레트의 표시 이름은 현재 한국어로만 등록되어 있습니다.
### Graph RAG 검색

볼트 검색은 벡터 유사도만 쓰지 않고, 검색된 노트의 링크를 따라 이웃 노트까지 후보에 넣습니다.

동작 순서:

1. **청크 임베딩** — 노트를 기본 2000자 단위(겹침 200자)로 분할해 청크마다 임베딩을 만듭니다. 긴 노트에서 관련 있는 부분만 걸리도록 하기 위함입니다.
2. **그래프 순회** — 검색으로 찾은 시드 노트의 outlink/backlink를 따라 이웃을 확장합니다. 탐색 깊이(hop)는 0~3, 기본 1이며 0이면 순회를 하지 않습니다.
3. **최소 관련성 필터** — 감쇠를 적용하기 **전**의 관련성이 0.55 미만인 후보를 제외합니다. 무관한 노트가 "관련 있음"으로 노출되는 것을 막습니다. 후보가 전부 걸러지면 키워드 검색으로 폴백합니다.
4. **통합 점수** — 살아남은 후보의 관련성에 그래프 거리 감쇠를 **곱해** 0.0~1.0 범위의 통합 점수를 냅니다(`관련성 × 0.5^hop`). 이웃 노트의 관련성 자체는 `이웃 자신의 유사도 × 0.6 + 시드 유사도 × 0.4`로 계산합니다.

필터가 감쇠보다 앞에 오는 이유는, 감쇠 후 점수에 임계값을 걸면 hop 1 이웃의 이론적 최대값(1.0 × 0.5 = 0.5)이 임계값 0.55보다 낮아 그래프 이웃이 전량 제거되기 때문입니다.

#### 임베딩 모델 변경 감지

인덱스에는 임베딩 구성 시그니처(`bedrock:{모델 ID}`)와 벡터 차원이 함께 저장됩니다.

- 임베딩 모델을 바꾸면 기존 벡터는 다른 임베딩 공간에 속하므로 폐기되고, 키워드 검색으로 폴백하며 재인덱싱 안내가 표시됩니다.
- 차원이 맞지 않는 벡터는 "비교 불가"로 처리됩니다. 유사도를 0으로 계산해 모든 노트가 동점이 되는 상황을 방지합니다.
- 일부 노트만 차원이 다른 경우(재인덱싱 진행 중 등)에는 비교 가능한 후보로 검색을 계속하되, 인덱스가 낡았음을 함께 알립니다.

#### 설정

| 설정 | 기본값 | 설명 |
|------|--------|------|
| 그래프 순회 깊이 | 1 | 검색 결과에서 링크를 따라 확장할 hop 수 (0~3, 0이면 그래프 순회 비활성) |
| 청크 최대 크기 | 2000 | 단일 청크의 최대 글자 수 (최소 1) |
| 청크 겹침 크기 | 200 | 인접 청크 간 겹침 글자 수 (청크 최대 크기보다 작아야 함) |

### Second Brain Layer (LLM Wiki)

Graph RAG가 볼트를 "읽는" 계층이라면, Second Brain Layer는 그 위에서 볼트에 "쓰는" 계층입니다.

> **기본적으로 꺼져 있습니다(옵트인).** 설정 → Second Brain → "Second Brain 활성화"를 켜야 동작합니다. 꺼져 있으면 관련 커맨드는 안내 메시지만 반환하고, 노트 생성·수정도 열람 이력 수집도 하지 않습니다.

#### 노트를 덮어쓰지 않는 이유 — Sentinel 블록

생성 도구가 만드는 영역은 `<!-- @generated:KEY -->` ~ `<!-- @end:KEY -->` 마커로 감싸집니다. 재실행하면 **그 블록 안쪽만** 교체되므로, 같은 노트에 직접 적은 메모는 그대로 남습니다(멱등 갱신). LLM 응답에 이 마커와 같은 문자열이 섞여 나오면 블록 구조를 깨지 않도록 무해화됩니다.

#### 읽기 전용 도구 (노트를 만들지 않음)

결과를 채팅으로만 돌려주며 볼트에 아무 쓰기도 하지 않습니다.

| 도구 | 커맨드 | 하는 일 | LLM 호출 |
|------|--------|---------|----------|
| `challenge` | 주장 반박 (challenge) | 과거 노트를 근거로 현재 주장의 허점·반례·전제를 비판 | 1회 |
| `connect` | 두 주제 연결 (connect) | 두 주제를 각각 검색해 교차 컨텍스트로 묶고 연결 아이디어 도출 | 1회 |
| `emerge` | 최근 패턴 발견 (emerge) | 최근 N일 노트에서 아직 이름 붙지 않은 패턴 발견 | 1회 |
| `reconcile_topic` | 모순 점검 (reconcile) | 노트 간 상충하는 진술을 점검해 리포트로 제시 (노트 미변경) | 1회 |

`emerge`는 최근 노트 60건까지만 분석합니다. 초과한 경우 몇 건 중 몇 건만 분석했는지 결과에 함께 알립니다(조용한 누락 방지).

#### 생성 도구 (노트를 만듦)

| 도구 | 커맨드 | 하는 일 | LLM 호출 |
|------|--------|---------|----------|
| `synthesize_topic` | 주제 종합 (synthesize) | 주제 관련 노트를 종합해 위키 노트 생성/갱신 (synthesis 블록만 교체) | 1회 |
| `architect` | 코드베이스 아키텍트 (architect) | 폴더·모듈·진입점을 스캔해 아키텍처 노트 생성/갱신 | 3회 (overview / modules / decisions 각 1회) |
| `create_wiki_note` | 위키 노트 생성 | 위키 폴더에 프론트매터 + 프리앰블 규격 노트 생성 | 0회 |
| `update_index` | 위키 인덱스 갱신 | 위키 폴더 노트를 모아 `index.md` 카탈로그 갱신 (사용자 메모 보존) | 0회 |

`architect`는 모듈 골격을 400줄까지만 프롬프트에 넣습니다. `synthesize_topic`은 검색 결과가 없으면 노트를 만들지 않습니다.

`architect`와 `update_index`는 임베딩 인덱스를 쓰지 않고 볼트 파일 목록을 직접 읽으므로, 인덱싱하지 않은 볼트에서도 동작합니다.

#### 안전 장치

- **위키 폴더 밖 쓰기 차단** — `..` 세그먼트, 절대 경로, 윈도우 드라이브 문자(`C:`)를 경로 세그먼트 단위로 거부합니다.
- **경로 충돌 시 덮어쓰지 않음** — `create_wiki_note`는 같은 경로에 노트가 이미 있으면 생성하지 않습니다.
- **파괴적 도구 실행 확인** — 설정 → 노트 변경 확인을 켜면 노트를 생성·편집·삭제·이동하는 도구 실행 전에 확인 대화상자를 표시합니다.
- **낡은 인덱스 경고** — 임베딩 모델 변경으로 인덱스를 신뢰할 수 없는 상태에서 결과를 만들면 경고 문구를 결과에 덧붙입니다.

#### 스케줄러 (Cleanup_Pipeline)

설정에서 별도로 활성화하며(기본 꺼짐), **Obsidian을 시작할 때** 마지막 실행에서 설정 주기(기본 24시간)가 지났는지 확인해 다음 4단계를 실행합니다. 백그라운드 타이머로 돌지 않으므로 앱이 켜져 있는 동안 주기가 지나도 그때 바로 실행되지는 않습니다. 모두 비파괴 작업이며 **LLM 호출은 0회**입니다.

1. 위키 폴더와 카테고리 폴더(`entities` / `concepts` / `projects`) 보장
2. `index.md` 카탈로그 갱신 (catalog sentinel 블록만 교체 → 사용자 메모 보존)
3. 지식 공백 리포트 갱신
4. `log.md`에 실행 이력 한 줄 append (기존 로그 불변)

한 단계가 실패해도 격리되어 나머지 단계는 계속 실행됩니다. 모든 단계가 실패하면 마지막 실행 시각을 갱신하지 않으므로 다음 트리거에서 재시도합니다. 커맨드 팔레트의 "Second Brain 정리 실행 (스케줄러)"로 즉시 실행할 수도 있습니다.

#### 설정

| 설정 | 기본값 | 설명 |
|------|--------|------|
| Second Brain 활성화 | 꺼짐 | 이 레이어 전체의 옵트인 스위치 |
| 위키 폴더 | `Second Brain` | Second Brain 노트를 생성·관리할 루트 폴더 |
| 스케줄러 활성화 | 꺼짐 | Obsidian 시작 시 Cleanup_Pipeline 자동 실행 여부 |
| 스케줄러 주기 (시간) | 24 | 자동 실행 간 최소 시간 (최소 1) |

### 지식 공백 리포트

인덱스 데이터만으로 볼트의 구조적 공백을 계산합니다. **LLM 호출 0회**이며 자동 수정은 하지 않습니다 — "볼 곳"만 제시합니다.

네 가지 지표를 봅니다:

| 지표 | 판정 기준 |
|------|-----------|
| 참조되지만 없는 노트 | 여러 곳에서 링크하는데 아직 만들지 않은 노트 |
| 내용이 부족한 노트 | 백링크는 있는데 본문이 200자 미만 |
| 어디에도 연결되지 않은 노트 | outlink·backlink가 모두 없어 그래프 순회로 도달 불가 |
| 한 방향으로만 연결된 노트 | 링크가 한쪽 방향만 존재 |

상위 20건이 `{위키 폴더}/Knowledge Gaps.md`에 sentinel 블록으로 기록됩니다. 커맨드 팔레트의 "지식 공백 리포트 갱신"으로 수동 실행하거나, 스케줄러 파이프라인에서 자동 갱신됩니다. Second Brain 활성화가 필요합니다.

### 복습 큐

오래 열지 않았지만 링크가 많은 노트 5건을 제시합니다. 커맨드 팔레트의 "복습 큐 (다시 볼 노트)"로 실행하며 **LLM 호출 0회**입니다.

- 점수는 마지막 열람 이후 경과 일수 + 링크 수로 계산합니다.
- 본문 200자 미만인 노트와 최근 7일 내 이미 제시된 노트는 제외합니다.
- 노트에 등급·복습 필드를 심지 않습니다. 열람 이력은 플러그인 설정에만 저장합니다.
- 열람 이력이 없는 도입 초기에는 노트 수정 시각으로 폴백합니다.
- 삭제·이동된 노트는 이력에서 정리됩니다.

Second Brain 활성화가 필요합니다. 꺼져 있으면 열람 이력 자체를 수집하지 않습니다.

### 대화 결론 수확

대화 세션은 최대 50개까지 보관되며 오래된 것은 밀려나 사라집니다. 사라지기 전에 쓸 만한 결론만 볼트로 옮기는 기능입니다.

1. 사이드바에서 세션 목록 열기
2. 세션 행의 수확 버튼(새싹 아이콘) 클릭
3. 결론·결정·근거·미해결 질문만 추출되어 `{위키 폴더}/Conversations/YYYY-MM-DD 제목.md`로 저장됩니다

원본 대화는 저장하지 않습니다. 잡담·시행착오·중간 오류까지 인덱싱되면 이후 검색 근거의 품질이 떨어지기 때문입니다. 저장된 노트는 일반 마크다운이므로 증분 인덱서가 자동으로 인덱싱해 이후 검색 근거가 됩니다.

**수확 1회당 LLM 1회**를 호출합니다. 수동 트리거만 제공하며(자동 수확 없음) Second Brain 활성화가 필요합니다.
