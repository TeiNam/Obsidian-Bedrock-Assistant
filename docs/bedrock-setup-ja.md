# Bedrock APIキー設定ガイド

Agent LLMsのBedrockバックエンドは、**Bedrock APIキー（ベアラートークン）**1つで認証します。端末ごとに一度入力すれば完了で、再ログインはありません。

## なぜAPIキーのみなのか

0.3.0で`~/.aws`プロファイル認証（SSO含む）と長期アクセスキー認証を削除しました。

| 方式 | 削除理由 |
|---|---|
| AWSアクセスキー | 長期資格情報のためリスクが最も大きい。キーが空のときSDKのデフォルト認証チェーンにフォールバックし、意図しないアカウントで呼び出される不具合もありました |
| `~/.aws`プロファイル（SSO） | 端末ごとに`aws sso login`が必要で、トークンが8〜12時間ごとに期限切れになります。複数端末で使うノートアプリには負担が大きいです |
| IAM Roles Anywhere | 端末ごとに別のX.509証明書を発行する必要があります。証明書をコピーすると端末識別が無意味になるため、設計上共有できません |

Bedrock APIキーは端末ごとに一度入力すれば済み、有効期限管理はAWSコンソールで行います。

## 前提条件

| 項目 | 要件 |
|---|---|
| AWSアカウント | Bedrockを使用するリージョンでモデルアクセスが有効化されている必要があります |
| IAM権限 | 以下の4つ |
| プラグイン | デスクトップ専用です |

```
bedrock:InvokeModelWithResponseStream
bedrock:InvokeModel
bedrock:ListFoundationModels
bedrock:ListInferenceProfiles
```

`bedrock:ListInferenceProfiles`も必要です。チャットモデルはドロップダウンからのみ選択できるため、この権限がないとリストが空になりモデルを選べません。

## 1. モデルアクセスの有効化

AWSコンソール → Bedrock → **Model access**で使用するモデルを申請します。リージョンごとに個別に申請する必要があります。

最低でもチャットモデル1つと埋め込みモデル1つが必要です。埋め込みモデルはボルトインデックス化（Graph RAG）に使用され、プラグインはAmazon TitanとCohere Embedファミリーをサポートしています。

ターミナルから確認するには:

```bash
aws bedrock list-foundation-models \
  --region ap-northeast-2 \
  --query 'modelSummaries[?outputModality==`EMBEDDING`].modelId' \
  --output table
```

リストが空の場合、そのリージョンでまだ有効化されていません。

## 2. APIキーの発行

AWSコンソール → Bedrock → **API keys**で発行します。

キーには2種類あります。

| 種類 | 有効期間 | 用途 |
|---|---|---|
| 短期（short-term） | 最大12時間 | 一時的なテスト |
| 長期（long-term） | 発行時に指定（最大無期限） | このプラグイン |

**長期キーを発行してください。** 短期キーは12時間後に期限切れになり、再入力が必要です。

キーは発行直後に一度だけ表示されます。その場でコピーしてください。

> 発行されたキーは特定のIAMユーザーの権限をそのまま使用します。最小権限の原則に従い、上記4つの権限のみを持つユーザーで発行する方が安全です。

## 3. プラグイン設定

1. 設定 → **Agent LLMs**を開きます
2. **AIバックエンド**を`Bedrock`に設定
3. **Bedrock APIキー**に発行したキーを貼り付け（目のアイコンで値を確認可能）
4. **AWSリージョン**にモデルを有効化したリージョンを入力（例: `ap-northeast-2`）
5. **Bedrock チャットモデル**と**Bedrock 埋め込みモデル**をドロップダウンから選択

モデルドロップダウンが空の場合は権限かリージョンの問題です — 下記のトラブルシューティングを参照してください。

### キーはボルトに保存されません

APIキーはOSキーチェーン（macOS Keychain、Windows DPAPI、Linux libsecret）で暗号化して、Electron userDataディレクトリのローカル専用ファイルに保存します。ボルトの`data.json`には残らないため、ボルトをクラウド同期してもキーは伝播しません。

OSキーチェーンを使用できない環境では、キーを**ファイルに一切書き込みません。** 平文でディスクに残さないための動作で、この場合プラグインを再起動するたびにキーを再入力する必要があります。

## 複数端末での使用

端末ごとに**APIキーを一度入力すれば完了です。** 再ログインや証明書発行はありません。

| 項目 | 同期 | 対処 |
|---|---|---|
| APIキー | ✗（意図的） | 端末ごとに設定で入力 |
| プラグイン設定（モデル・リージョン） | ○（ボルト同期時） | 自動 |
| ボルトインデックス | ○ | 以下参照 |

同じキーを複数端末で使用しても、端末ごとに異なるキーを発行しても構いません。**端末ごとに発行すれば、1台を紛失したときにそのキーだけを無効化できます。**

### ボルトインデックスは端末間で共有されます

ボルトを同期すると`.agent-llms-index.json`も一緒に移動します。埋め込みベクトルが含まれるため数十MBになる可能性があります。

**埋め込みモデルが同じなら**、新しい端末で再インデックス不要で検索がすぐに動作します。プラグインは`{provider}:{model ID}`形式のシグネチャで判断します（例: `bedrock:amazon.titan-embed-text-v2:0`）。

**埋め込みモデルが端末ごとに異なる場合**、シグネチャが一致せず既存ベクトルが破棄され、再インデックスの案内が表示されます。その間検索はキーワード方式で動作します。端末間で埋め込みモデルを同じにすればこの問題は発生しません。

同期ツールがドットで始まるファイルを除外するよう設定されている場合、インデックスは移動しません。その場合新しい端末で一度インデックス化してください。

## トラブルシューティング

### `Bedrock API 키가 설정되지 않았습니다`（Bedrock APIキーが設定されていません）

設定でキーを入力してください。プラグインはキーが空のとき**意図的に失敗します** — AWS SDKのデフォルト認証チェーンにフォールバックすると、`~/.aws/credentials`の`[default]`プロファイルや環境変数、IAMロールが静かに使用され、選択していないアカウントにノートが送信され課金される可能性があります。

キーを入力してもこのエラーが出る場合、OSキーチェーンを使用できない環境の可能性があります。その場合キーはファイルに保存されないため、プラグイン再起動ごとに再入力が必要です。

### モデルドロップダウンが空です

3つを確認してください。

1. リージョンが正しいか — モデルを有効化したリージョンと設定のリージョンが一致している必要があります
2. モデルアクセスが有効化されているか — セクション1の`aws bedrock list-foundation-models`コマンド
3. 権限 — チャットリストは`bedrock:ListInferenceProfiles`、埋め込みリストは`bedrock:ListFoundationModels`が必要です

モデルはドロップダウンからのみ選択できるため、リスト取得権限がないとモデルを設定できません。上記の権限をIAMポリシーに追加してください。

### `ExpiredTokenException`または`401`

短期APIキー（最大12時間）を使用している可能性が高いです。コンソールで長期キーを新規発行して置き換えてください。

### `AccessDeniedException`

キーに紐づいたIAMユーザーに上記の権限がないか、呼び出そうとしているモデルへのアクセス権限がありません。コンソールのModel accessで該当モデルの状態を確認してください。

### `ValidationException`（埋め込み呼び出し時）

サポートされていない埋め込みモデルの可能性があります。プラグインはAmazon TitanとCohere Embedファミリーのみリクエスト・レスポンススキーマを実装しています。ドロップダウンはサポートモデルのみ表示しますが、古い設定に別のモデルIDが保存されている場合このエラーが発生する可能性があります。

### 埋め込みモデルを変更したら検索結果がおかしいです

埋め込み次元が変わると既存ベクトルと比較できません。プラグインがこれを検出して旧ベクトルを破棄し、再インデックスの案内を表示します。案内に従ってボルトを再インデックス化してください。それまで検索はキーワード方式で動作します。

## ネットワーク使用

| 対象 | 目的 |
|---|---|
| `bedrock-runtime.{region}.amazonaws.com` | チャット・埋め込み呼び出し |
| `bedrock.{region}.amazonaws.com` | モデルリスト取得 |

資格情報はローカルにのみ保存されます。サードパーティの分析や追跡サービスにデータは送信されません。
